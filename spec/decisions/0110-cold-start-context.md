# 0110. The context of a cold-start project: every schema field, every enum member and every built-in signature, generated from the registry (`contextFormat` 2)

- Status: Accepted
- Date: 2026-10-19
- Blueprint origin: M7 (blueprint §11), follow-up K-01 of the AI/token benchmark; blueprint §3.4 (one registry), §9.2 (a neighbourhood, not the whole library); `spec/ai-and-benchmarks.md` §2; decisions 0072 (the context export), 0108 and 0109 (the benchmark and its pilot).
- Supersedes: the field objects, the empty `schemas` of a project without code and the numbering `contextFormat` 1 of decision 0072. Nothing else of it: the neighbourhood, the example selection, the derivation of `supported` and the failure modes stand.

## Context

The pilot of decision 0109 found that the compiler context of a cold-start task has `schemas: []`, `examples: []` and `symbols: []`: a feature list and syntax rules, 7.5 kB. The model then invents what it is not told: `vfov`, `vertical_fov` and `near_plane` for `fov_y` and `near`, `Key.Up` for `Key.ArrowUp`, `color.linear(r, g, b)` for `color.linear(rgb, a)`, light units. Five of the twelve guide-run attempts that did not compile started with an invented field name, and each costs repair rounds, which are tokens. A project that has code teaches this by example; one that has none cannot.

## Decision

1. **What a cold start is** (proposal). A project whose declarations are, all of them, scenes, scene objects (cameras), `state` and `param`: it declares no entity, prefab, material, function, constant or struct. An empty entry module, one that does not parse and `scene Demo { camera Main {} }` are cold; one entity makes a project warm. This is read from the declarations the context already computes (`context::reference::is_cold`); it needs no task metadata and no flag, so an editor, a harness and a person get the same document for the same project. A warm project keeps the selection of decision 0072 unchanged: the schemas its neighbourhood uses, its examples, no library.
2. **What a cold start gets, in addition to the neighbourhood.**
   - `schemas`: every implemented schema that has fields, sorted by name, not only those the project uses. Each carries the registry `doc` of the schema and, on each field line, the range and the registry `doc` of the field (units, meaning, the rule between two fields). A schema without fields (`Static`, `Kinematic`) is not listed: the field that takes it names it.
   - `reference` (new key), five lists and the conventions, each a section that `--max-bytes` can drop whole: `enums` (every implemented member of every enum, `doc` of the enum, in registry order), `typeClasses` and `builtins` (the signature of every global function and every namespace member, with argument names; the plain mathematical functions share a line by signature, `min|max(a: T, b: T) -> T`; the registry `doc` follows ` // ` for everything else; the tags `[cpu only]`, `[gpu only]` and `[handlers and lifecycle functions only]` come from the registry's domain and `handlers_only`), `events` (`on key_down(Key.<member>)`, `on pointer_down(<name>: PointerEvent)`, the hosts where not every body can host the handler), `records` (`PointerEvent`, `SurfaceInput` with their fields), `body` (the body commands with their arguments and the bodies that take them, the readable properties with their documentation) and `conventions` (decision 0111).
   - `examples` stays empty (decision 0112 item 3).
3. **Everything is read from the registry** (constraint of blueprint §3.4). The code that builds the section chooses where to put a registry fact and how to spell a signature; every word that is not a spelling is a `doc`. A test lists every implemented schema field, enum member, intrinsic and namespace signature, event, record and body command of the registry and fails when one is missing from the context of an empty project, so a registry row added tomorrow shows up there without anyone editing the exporter.
4. **`contextFormat` 2.** Decision 0072 bumps the number when a key is added while the schema forbids unknown keys, and a key is added (`reference`, `schemaGuide`). A schema field is now **one line of text** instead of an object: `name: type = default [flags]`, and for a cold start `name: type = default [flags] range R // meaning`. The object cost some 160 bytes per field for four fixed keys and the indentation of a pretty-printed document; the line costs the text only, which is what lets the library fit (decision 0112). `schemaGuide` explains the line and the flag letters (R required, W writable from handlers, B bindable, C construction-only); it is shorter for a warm project, whose lines have no range and no meaning. `enums[].members` is one string separated by spaces, for the same reason. `spec/context.schema.json` is updated with the new keys, a pattern for a field line and a `minProperties` of 1 for `reference` (an empty one is not emitted); `tools/ai-eval` requires format 2.
5. **Truncation.** `reference` sections are a new phase of the order of decision 0072 item 8, after the neighbour symbols and before the schemas: examples, neighbours, the sections of `reference` (records, body, events, builtins with `typeClasses`, conventions, enums), schemas, requested symbols. `truncated.reference` lists the names of the sections dropped. For a cold start the library is worth more than the examples a stub would have been shown (they were four, 3 kB, and dropped first by any budget that holds the library), so a cold start has none.
6. **A schema's field list is the registry's, filtered by `since`** exactly as before (`is_implemented`): a field or an enum member the build does not implement is not listed, and the planned ones stay under `notSupported`.

## Consequences

- A model that reads the context of an empty project is told, from the registry, every field of every schema (`fov_y`, not `vfov`), every key (`ArrowUp`), the arity of `color.linear` and `quat.euler`, and the units of every quantity that has one. What it does with this is a measurement (M7-05 phase 2), not a claim of this record.
- The context of a project with code is **smaller**: a field line replaces an object. Sizes are in decision 0112.
- The library is in the context of a cold start whether or not the task needs physics or glTF; decision 0112 lists what had to be left out for the whole to fit 24 000 bytes and what that costs.
- `docs/language-reference.md` carries registry `doc` text and is regenerated; the registry docs changed by this task are listed in decision 0111.
