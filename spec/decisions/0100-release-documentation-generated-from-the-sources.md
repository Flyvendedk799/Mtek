# 0100. The release documentation is generated from the specification, the registry and the compiler

- Status: Accepted
- Date: 2026-10-19
- Blueprint origin: M7 (blueprint §11), task M7-06 ("Release documentation and capability consistency check"); decisions 0091 (the getting-started page is executed), 0093 (the coverage matrix is generated and its staleness is tested), 0072 (the context export lists what the build supports).
- Supersedes: nothing.

## Context

A language guide and a language reference written by hand drift: a feature is added to the registry and the page does not know, a restriction is lifted and the page still lists it. The project already has the remedy for one document (`docs/coverage-matrix.md`, decision 0093: generated by a tool, with a test that fails when the committed file is stale). M7-06 asks for the same for the language documentation: "generated/derived from `spec/` and the registry", with no hand-copied feature table that can drift.

## Decision

1. **A workspace package, `tools/release-docs` (`@mtek/release-docs`).** It follows `tools/coverage-matrix`: TypeScript run by Node 24 without a build step, its own `eslint`, `tsc` and `vitest`, one command (`npm run check:release`, `npm run generate -w @mtek/release-docs`). It reuses the facts of the coverage tool rather than re-deriving them: the compiler runner and `findMtek`, `readSupported` (`mtek context`), `readCatalogue`, `readExceptions` and `readFixtureCodes` of `tools/coverage-matrix/src`.
2. **Three pages are generated; nothing in them is typed by hand.**
   - `docs/language-reference.md`: Part A is the normative text of `spec/language.md`, verbatim (the metadata block is dropped and the headings are demoted one level; fenced code is untouched); Part B is the standard library, printed from `spec/stdlib-schema.json` (types, schemas with every field, its type, default, update class and range, scene objects, events, enums with their DOM codes, namespaces, intrinsics, body commands and properties); Part C is `supported.features` of `mtek context`, grouped by kind; Part D is the table of diagnostic ranges of `spec/diagnostics.md` with the number of codes per range.
   - `docs/language-guide.md`: a template (`tools/release-docs/templates/language-guide.md`) whose prose is hand-written and whose programs and facts are expanded by the generator. A program is never typed into the template: `{{example PATH}}` copies a whole file of the repository and `{{excerpt PATH :: FROM :: TO}}` copies the lines between two patterns (a pattern that matches nothing is an error), so every code block of the guide is a file that the compiler's own suites check. Facts in the prose (the number of features, the events, the types, the schemas of a category, the host input codecs, the commands) are `{{...}}` directives read from the compiler, the registry and `spec/manifest.schema.json`.
   - `docs/limitations.md`: decision 0103.
3. **The staleness test.** `npm run check:release` (and the unit test of the package) regenerates the three pages in memory and compares them with the committed files; a difference fails with the first differing line of both. `npm run generate -w @mtek/release-docs` rewrites them.
4. **Hand-written, and kept honest by other means.** `docs/release-notes-v0.1.md` (decision 0104), `docs/getting-started.md` (executed by `crates/mtek-cli/tests/getting_started.rs`, decision 0091) and the `README.md` (compared with the compiler and `package.json` by decision 0101).
5. **What the generator needs.** The built `mtek` (the same requirement as `npm run check:coverage`, and the same message and exit code 3 when there is none) and Node 24.

## Consequences

- A registry row, a construct, a reserved word, an `x9xx` code or a reason that changes changes the pages in the same commit, or CI fails.
- The reference repeats `spec/language.md`. That duplication is deliberate and cannot drift: the copy is regenerated and compared.
- The guide teaches with the three demonstrations and the first example; if an example's text changes so that an excerpt's pattern no longer matches, the generator fails and names the pattern and the file.

## Verification

`npm run check:release`; `npm run test:unit -w @mtek/release-docs` (the generated pages equal the committed ones; the directives and readers have unit tests); the mutation of a committed page in `test/live.test.ts` ("a stale generated page fails docs/stale"). Recorded in the completion report of M7-06.
