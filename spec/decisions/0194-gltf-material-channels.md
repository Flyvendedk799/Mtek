# 0194: Core glTF material channels and mip-aware sampling

Date: 2026-10-25. The mixed-filter restriction is amended by [decision 0200](0200-independent-gltf-sampler-filters.md). Implementation increment after decision 0193. This amends the
material restrictions of 0015, the resource limit of 0054, and the five-parameter
`Pbr` declaration of 0057. Validation and retained run records are in
`evidence/platform-step/rendering-channels-progress.md`.

## Material contract

1. The existing `Pbr` material retains its original five parameters. It adds
   `metallic_roughness_texture/sampler`, `normal_texture/sampler`,
   `occlusion_texture/sampler`, `emissive_texture/sampler`, `normal_scale`,
   `occlusion_strength` and `emissive`. Each map defaults to white and each sampler
   to `sampler.linear_repeat()`. `normal_scale` defaults to zero, disabling the
   non-neutral white fallback; `occlusion_strength` defaults to one, and `emissive`
   to opaque black. A hand-authored normal map must explicitly set `normal_scale`.
2. The strict GLB profile accepts the corresponding core glTF slots, including
   `emissiveFactor`. Every slot requires UV set zero. OPAQUE, single-sided
   materials remain the profile; alpha modes, extra UV sets, authored tangents
   and material extensions retain their explicit rejection. `glb_asset.material`
   imports every supported channel and retains the concrete `Pbr` schema so
   application code can access its parameters by name. Absent GLB normal maps
   set scale zero; present maps use `normalTexture.scale`, default one.
3. Base-colour and emissive images are sRGB; metallic-roughness, normal and
   occlusion images are linear data. Image packaging deduplicates by content and
   colour space. The same source image used as both colour and data produces two
   uploads; MR and AO references to the same linear image share an upload.
4. Sampled blue multiplies metallic; green multiplies roughness before the
   existing BRDF clamps. Sampled red occlusion gives
   `1 + clamp(strength, 0, 1) * (red - 1)` and scales ambient light only. Emissive
   colour multiplies the emissive texel and is added before camera exposure.
   Output remains LDR without tone mapping. Transparency follows the existing
   colour-alpha classification; this does not add glTF alpha modes.
5. `lighting.pbr` remains available with its existing signature and arithmetic.
   `lighting.pbr_mapped(surface, albedo, metallic, roughness, normal_texel,
   normal_scale, occlusion, emissive)` adds the mapped inputs. Its normal uses a
   cotangent frame derived from world-position and UV screen derivatives,
   including mirrored UVs. Map RGB decodes from `[0, 1]` to `[-1, 1]`, scale
   multiplies XY, and the resulting world normal is normalized. Degenerate
   derivative frames and zero decoded vectors use the geometric normal.
   This is not authored MikkTSpace tangent parity. Tangent import and that
   compatibility workflow remain separate work.

## Sampling and limits

6. `sample` retains its explicit level-zero behavior, including use inside
   divergent branches. `sample_mip(texture, sampler, uv)` uses implicit
   screen-space mip selection. `Pbr` uses the latter for every map, so the chains
   generated by 0193 now affect minified material draws.
7. Derivative operations have a conservative source-level rule: calls to
   `sample_mip` and `lighting.pbr_mapped` must appear in a fragment's initial
   straight-line prefix, before any branch, loop, match, nested block or
   short-circuit expression. They cannot be hidden inside user helper functions.
   Otherwise `check` reports `E4042`. Evaluate a texel first and branch on its
   value afterwards. This rejects some uniform programs intentionally; it is
   not a general uniformity analysis. It avoids passing invalid derivative
   control flow to generated-WGSL validation.
8. The four existing sampler presets retain their filters. Each has a `_level0`
   variant with `lodMaxClamp: 0`. Linear presets add `_mip_nearest`; nearest
   presets add `_mip_linear`. GLB import selects the variant matching its
   requested mip filter, including non-mip filters. The existing restrictions on
   differing min/mag filters, mirrored repeat and differing U/V wrap modes remain.
9. Combined texture and sampler params increase from eight to sixteen, with
   `E6002` at the seventeenth. This permits five independent texture/sampler
   pairs while fitting the current renderer's WebGPU default per-stage texture
   and sampler limits. Material value and resource layouts are regenerated when
   rebuilding; existing compiled manifests retain their own declared layouts.

## Starter reference budget

10. The expanded material API exceeds the starter reference's 30,000-byte budget
    with pretty printing. Cold-start contexts now use compact JSON plus a trailing
    LF, without changing any keys, values or context format version. Warm contexts
    retain their existing formatting. Cold contexts retain compact formatting after
    reference truncation, keeping the fitter's size ordering monotonic. Registry
    documentation is concise; every schema field, signature and enum member remains
    present with at least 1,000 bytes reserved for project symbols. This amends the
    whitespace choices of 0072 and 0172, preserving their completeness and budget.
11. Release/preview manifests and WGSL span-map documents use compact JSON with
    a final LF. Development/test output remains indented. Expanded mapped shaders
    otherwise exceeded four existing example package budgets; removing JSON
    whitespace reduces shipping bytes while retaining every diagnostic mapping,
    symbol and layout. Schema/ABI versions, field order and shader hashes are
    unchanged. Parsed release/dev metadata equality is checked on a real package;
    reproducibility and schema validation continue across the fixture corpus.

## Validation and remaining scope

The corpus adds complete imported-map, normal-only and emissive-only projects;
reader checks for slot factors and UV restrictions; and negative derivative
control-flow fixtures. Browser tests cover regular, mirrored and
degenerate UVs against an independent f64 BRDF oracle, plus actual minified mip
selection versus level-zero sampling. The final GPU run passes 42 checks across
hardware and SwiftShader, including recovery and disposal. Package/schema,
code-generation, starter-reference and documentation checks are recorded alongside
the results; all existing package-size limits hold without increases.

Shadows, environment lighting, HDR, authored tangents and matched-engine visual
and performance comparisons remain outside this increment. The reference for
channel semantics is the [Khronos glTF 2.0 specification](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#materials).
