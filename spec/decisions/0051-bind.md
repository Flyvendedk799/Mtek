# 0051. `bind`: checks, dependency graph and per-frame evaluation: details the specification leaves open

- Status: Accepted
- Date: 2026-10-06
- Blueprint origin: M3 (blueprint §11), task M3-05; `spec/scenes.md` §§8.2, 8.4, 10, 11; `spec/runtime-abi.md` §§3, 5.2; decisions 0025, 0049, 0050.
- Supersedes: nothing. Lifts the M3 gating of `bind` (decision 0025).

## Decision

1. **Where.** `bind(expr)` is the whole value of a field the registry marks bindable (entity `position`, `rotation`, `scale`, `visible`; camera `position`, `target`, `rotation`) or of a param in the `material` of an entity (user or registry material). Anywhere else is `E5004`, including in struct or other descriptor literals and in a material literal that is not an entity's `material`. Camera projection fields are bindable in the registry but **not yet supported** here: they are `E5004` (limitation).
2. **Checking.** The bound expression is a CPU root body typed against the field's exact type (`E3102`). Purity is checked locally: a call of a `cpu fn` or CPU intrinsic is `E5005`. Reading a camera field is also `E5005`, because the manifest has no camera dependency kind. Bindings are checked after the whole scene body is typed, so they may read anything of the scene wherever declared.
3. **Dependencies and order.** Dependencies are the state, `frame` members, entity fields, entity state and material params read, in source order, each once. A binding reads another when it reads what the other writes. Evaluation order is topological with ties by declaration order (`order` in the manifest; `id` is declaration order). A cycle (a binding reading its own target included) is one `E5075` at the first binding of the cycle with every binding of it as a related span, in order.
4. **Single writer.** An assignment from a lifecycle function or handler to a bound field or param is `E5070`, at the assignment with the `bind` as related span. `E5072` (physics) is M5.
5. **IR and manifest.** A bound field or param has `Source::Bound(id)` (a stand-in constant is kept in the checked scene only); a bound param's update class is `bound`; the scene carries `bindings` with targets by static entity index (material params by instance index in the manifest) and dependencies. `init` does not set bound fields. `scenes[Name].bindings[id]` is `(ctx) => value`.
6. **Runtime.** After `init` every binding is evaluated once in manifest order (before the camera check and transform propagation), then every frame in phase 5 (conservative v0.1 policy: all of them). Values go through the validated setters (`E8090`, `E8100`); `setTransform` with an equal value does not mark the entity dirty; the arenas upload only changed bytes, so an unchanged bound value costs no upload. The scene object's `bindings` array must match the manifest (`E8003`).
7. **`mtek inspect --bindings`** shows each bound param's dependencies.

## Known limitations

- Non-constant field initialisers (a field initialiser reading state, without `bind`) are still `E9010`.
- Projection fields and light fields cannot be bound yet (lights arrive with M4).
