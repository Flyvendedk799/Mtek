# 0120. Change tracking in the frame: what is skipped when nothing changed, when an object block is written, and how it is kept correct (K-04, step 2); a defect of hot reload found and fixed

- Status: Accepted
- Date: 2026-10-19
- Blueprint origin: §6.3, §12.3; `spec/runtime-abi.md` sections 8 and 11; decisions 0055 (culling), 0059 (instancing), 0064 (spawn and destroy), 0099 (the follow-up candidates this carries out).
- Supersedes: item 4 of the header comment of `render/renderer.ts` and the sentence of decision 0055 that a culled entity's object block "is still written"; both are replaced by item 2 below.

## Context

Decision 0099 item 3(b) found that a constant scene paid a pass over every entity every frame (culling, batching, comparing 400 instance records word by word: 0.065 ms of render preparation against 0.020 ms), and item 3(a) that the 1,000 moving boxes wrote and uploaded 1,000 object blocks (128 bytes each, on a 256-byte stride) although the instanced draw reads none of them. Step 2 of task K-04 asks for entities whose inputs did not change to be neither visited nor re-uploaded, with a correct invalidation story for hot reload, spawn and destroy, parents, physics, bound and unbound params and device loss.

## Decision

1. **Decision: the world lists what it recomputed.** `World.propagate` returns at once when no transform was written since the last pass (a flag set by `setTransform` and by registering a spawned entity), keeps its scratch array, and rewrites every world matrix in place. It records the slots it recomputed in a list (a flag per slot says whether a slot is in it); `takeWorldChanges` returns that list once, in the order `propagate` recomputed the slots, each slot once, and drops slots that were unregistered meanwhile. A write of the value the entity already has (`setTransform` with an equal vec3 or quat) sets no flag (this was so before); a write to a parent recomputes its descendants (`recomputed[parent]`), as before. A world matrix is therefore a live array: nothing may keep it beyond the frame (the renderer copies it; `lights` reads it when it packs them).
2. **Decision: an entity's object block is written when a draw reads it.** For every slot in the change list the renderer compares the model matrix with the one it holds (`Object.is` on the 16 elements, so +0 and -0 differ as their bytes do); only when it differs does it refresh the entity's bounding sphere and its model and normal matrices (`entityMatrices`, the 32 words that are also the entity's instance record) and mark the object block stale. A stale block is written by `writeIndividualObjectBlocks`, after culling and batching, for the entities that are drawn individually in this frame; an entity that only takes part in instanced draws (which read the instance record and bind group 2 at an arbitrary slot), or is culled, or is invisible, keeps its block stale and has it written in the first frame in which it is drawn on its own. The bytes of every block a draw reads are the ones the earlier code wrote (the renderer test that reads them, the spawn golden test and the randomised comparison below say so); the bytes of a block nobody reads are no longer written. This is the one place where a GPU buffer holds something other than before. Layouts, the ABI, the pixels and every counter other than `uploads`/`uploadBytes` are unchanged.
3. **Decision: culling, batching and instance records are recomputed only for what changed.** `cull` is skipped when the draw list object, the view-projection matrix object, the culling switch and the spheres (only written when a world matrix changed) are the ones of the previous frame; otherwise it runs and compares its result with the previous one in place (`drawnUnchanged`). `groupDraws` reuses the batches when the culled draws are the same, and then visits only the instance records of the entities in this frame's change list (`recordOf`: entity to record), comparing their 32 words with the mirror of the GPU copy and uploading the range from the first to the last changed word; otherwise it rebuilds the batches and visits every record. A growth of the instance buffer, a rebuilt draw list (visibility, a block that was shared or detached, a spawn or a destroy) and `setFrustumCulling` force the full path. The staging array of the instance records is gone: records are compared and copied straight into the mirror.
4. **Decision: the view-projection matrix is a function of 13 numbers and recomputed only when one changes** (aspect, projection kind and its three parameters, the camera position, and the target or the rotation). It is the same `Float32Array` object while the camera is unchanged, which the culling test above uses. A failed view (`E8011`) is not cached, so it is reported every frame as before.
5. **Decision: the invalidation story**, one entry per thing the task listed:
   - *Hot reload (`replaceProgram`)*: a new `World` and a new `Renderer` are built from the candidate, so no cache survives. **A defect of the code before this decision was found by the randomised test and fixed:** `migrateWorld` assigns the carried `position`, `rotation` and `scale` of the records directly, not through the setters, after the candidate's `init` pass has cleared every dirty flag, and then called `propagate()`, which recomputed nothing; so after a reload every entity that had moved was drawn where the new `init` put it while its record said otherwise, until the program next wrote it. `migrateWorld` now calls `World.markAllTransformsDirty()` before that `propagate()`. `host/reload-transforms.test.ts` fails on the code of decision 0099 (x = 0 instead of 3) and passes now.
   - *Spawn and destroy (slot reuse)*: `addEntity` and `removeEntity` zero the slot's matrices, mark its block stale and clear its record, so the first world matrix of a successor is always seen as a change even when it equals its predecessor's (the randomised test found this one too: a spawned entity at a reused slot with the same pose was culled for ever because `removeEntity` zeroes the sphere). Registering a spawned entity sets the transform flag, so an entity that never writes its position still gets its first matrix.
   - *Parents*: `propagate` follows `recomputed[parent]` as before; the change list holds the parent and its descendants.
   - *Physics-driven transforms*: `PhysicsSystem.writeBack` writes the poses through `ctx.setTransform`, the same setter as a program's, so they take the same path; equal poses set no flag.
   - *Bound and unbound params*: unchanged: `writeParam` compares the written bytes with the mirror and marks the slot dirty only when they differ, in every case. The bindings are still all evaluated every frame (see item 7).
   - *Device loss*: `rebindParams` lists every slot as changed, and the renderer, the stores and the arenas are rebuilt, so the first frame after recovery recomputes everything.
   - *Material blocks that are shared or detached* (copy on write), a visibility change and `failMaterial` bump the versions the draw list already depended on; the list is rebuilt, the next `cull` and `groupDraws` see new draw objects and take the full path.
6. **Decision: the proof is a comparison with a full recompute, not a list of cases.** `render/change-tracking.test.ts` mounts the same program twice on the fake host: a tracked application, and a reference one whose world and renderer are told to forget their change tracking before every pass (`World.markAllTransformsDirty`, `Renderer.invalidate`, both used by nothing else in the runtime but the reload fix above). A seeded script of mutations (moves, rotations, scales also with the value the entity already has and with an invalid scale, visibility, the camera, parameter writes on shared blocks, spawn and destroy with slot reuse, hot reload at frames 30 and 61, device loss and recovery at frame 45, and one frame in six with no change at all) is applied to both; after every one of 91 frames of each of six seeds the draw calls, the counters that describe them and the bytes of every live GPU buffer must be equal. A second oracle that shares no code with the renderer works out from the entity records, with the allocating matrix functions and the frustum test, which world translations must be on screen, and compares them with the instance records and the object blocks the last pass reads. The test was checked by mutation: removing the `changedCount` condition of the culling skip, the early return of the instance update, the stale flag, the transform flag of `setTransform`, the `recordOf` reset, the fov in the view key, the zeroing of a forgotten slot, the sphere refresh, the descendants of a parent, or the listing of spawned slots each made it fail (the one mutation of a flag that only a spawn without a position write needs was caught after the script was extended to spawn such entities). `scene/world-tracking.test.ts` compares every world matrix after every pass of random writes with a recompute from the records and requires every changed matrix to be listed.
7. **Decision: not done, and why.** (a) *Skipping bindings whose dependencies did not change.* The manifest lists each binding's dependencies (`deps`), but handlers write scene and entity state directly, not through a setter, so a skip needs a by-value comparison of every dependency on every frame, and none of the seven frozen workloads has a binding without a `frame` dependency, so none would move; entities whose inputs did not change are not visited because an unchanged value is not written (`setTransform`, `writeParam`) and an unbound field has no binding. The policy of `scene/bindings.ts` (every binding every frame) is unchanged. (b) *Render bundles* to replay the encoding of unchanged draws would remove most of the remaining cost of the 500 individual draws, but they add a lifetime to every buffer, bind group and pipeline a bundle references and an invalidation rule for each; it is a design of its own. (c) The per-frame frame-block write (`writeIfChanged` of `MtekFrame`) still stages the block every frame; it is a few hundred bytes.

## Consequences

- A constant scene's frame no longer visits its entities: after the first frame its render preparation is the frame block, the draw encoding and the submit. The object arena of a scene that is drawn only by instancing is written once, at allocation, with zeros.
- A change that adds a new input of the render state (a new per-entity field read by culling or by the instance record) must be added to `change-tracking.test.ts`'s script, or the comparison cannot see it; the invalidation hooks are the place to reset it.

## Verification

- `render/change-tracking.test.ts` (8 tests: six seeds, a quiet-frames test, a test that the reference really recomputes), `scene/world-tracking.test.ts` (12), `host/reload-transforms.test.ts`, the updated `render/culling.test.ts` and `render/instancing.test.ts` (an entity that moved while instanced has the right block when it is drawn on its own), and the whole hardware browser suite.
