# 0016. v0.1 restrictions beyond the blueprint

- Status: Accepted
- Date: 2026-10-03
- Blueprint origin: §3.4, §6.1, §7.1, §8 (narrowings).

## Context

A few v0.1 specifications are deliberately narrower than blueprint text that describes the eventual behaviour. Each is listed here so the narrowing is visible, not accidental.

## Decision

1. **Collider rebuild deferred.** Blueprint §8 says changing collision dimensions "must use a defined rebuild path". In v0.1 collider dimensions are construction-only (`spec/physics.md` §2), so no rebuild path exists to define; changing them requires spawning a new entity. The rebuild path is specified when collider fields become writable (v0.2).
2. **Texture identity fixed per instance.** Blueprint §6.1 lists resource updates "when resource identity changes". In v0.1 `texture`/`sampler` params are construction-only (`spec/materials.md` §4), so identity never changes at run time; replacing a texture is v0.2.
3. **No recursion on the CPU either.** Blueprint §4.4 forbids recursion in GPU code. v0.1 forbids it in both domains (`spec/language.md` §8.2) — simpler effect analysis and identical rules for code that may run in either domain. Revisit with evidence of need.
4. **No opt-in to keyboard auto-repeat.** Blueprint §7.1 says auto-repeat is ignored "unless requested explicitly". v0.1 offers no way to request it; `key_down` fires once per physical press. An opt-in is added when a use case appears.

## Consequences

Each item yields an `x9xx` diagnostic or a documented limitation; none is silently approximated.

## Verification

Fixtures: collider field assignment rejected (`E5073`), texture param assignment rejected (`E5073`), recursion in a `cpu fn` rejected (`E4001`), auto-repeat events ignored (browser test with repeated `keydown` events).
