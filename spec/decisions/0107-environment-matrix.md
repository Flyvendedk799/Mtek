# 0107. The environment matrix: what an environment is, what counts as evidence for one, and a page that cannot list more than was run

- Status: Accepted
- Date: 2026-10-19
- Blueprint origin: M7 (blueprint §11), task M7-03 ("run the full browser suite on every available environment; store each environment record and result; produce `docs/supported-environments.md` listing exactly what passed, what failed and what was not run"); decisions 0012 (the browser configuration and the environment record), 0104 (release notes from evidence only).
- Supersedes: nothing.

## Context

Until M7 every hardware result came from one browser (Playwright's Chromium) on one machine, and the release notes said so. A list of "supported environments" is the kind of page that grows by assertion: a browser that opened a page once is written down as supported. The acceptance criterion is the opposite: the page lists only environments with stored evidence. The machine has more than one Chromium-based browser installed, can run Playwright's Firefox and WebKit, and the repository's CI has one Linux job whose result is on GitHub, not here.

## Decision

1. **An environment is one operating system, one browser build, one launch configuration and one adapter**, as written by the harness in an environment record (`tests/browser/environment.schema.json`, decision 0012). Its result is the counts of one Playwright project in that configuration. The existing records and the existing projects are used: `hardware`, `benchmarks` and `software` for every Chromium-based browser (`MTEK_BROWSER_CHANNEL=chrome` or `msedge` selects an installed Chrome or Edge; Playwright's bundled Chromium is the default).
2. **A browser that the projects do not launch is probed, not assumed.** `tests/browser/support/probe-browser.ts` loads the environment page in Firefox, WebKit or any Chromium channel with the same page-side probe and record writer, and stores the record (`navigator.gpu` present or not, the adapter or the reason for none). A browser with no adapter is **not run**, with that record as the reason.
3. **Firefox has an opt-in project, `firefox`, only when `MTEK_EXPERIMENTAL_BROWSER=firefox` is set** (`tests/browser/playwright.config.ts`). It is headed and sets `dom.webgpu.enabled` and `gfx.webgpu.ignore-blocklist`, because the probe showed Firefox 155 returns no adapter headless in the three configurations tried and returns one when headed with the preferences. The preferences are written into the environment record (`pref:name=value` in `launchArgs`). The default run is unchanged, so `npm run test:browser` stays a Chromium run. WebKit has no project: it exposes no `navigator.gpu`.
4. **CI evidence is quoted, never reproduced.** The result of the `browser-software` job of the latest run on `main` is downloaded from GitHub Actions (`gh run view`, `gh run download`, read-only), stored with its run id, URL, commit and job conclusions (`run.json`), and marked "as reported by GitHub Actions, not reproduced locally". It is software-adapter evidence (informational, as in `spec/testing.md`), and a red run is stored red. The commit it belongs to may not be the local commit; the page says which it is.
5. **Every run is stored under `evidence/M7/environments/<name>/`**: the environment records, the Playwright report passed through `npm run evidence:sanitize` (no absolute path), and `summary.md`/`summary.json` generated by `tests/browser/support/summarize-run.ts`, which counts passed, failed, NOT-RUN and skipped exactly as the run's own reporter does (`run-summary.ts`) and lists the failures and the skip reasons. The numbers on the page come from these summaries, not from the console.
6. **The page cannot list more than was run.** `docs/supported-environments.md` is hand-written, and `npm run check:release` holds it to the evidence (`tools/release-docs/src/environments.ts`): every row and bullet outside "How to read this page" must link to a file under `evidence/M7/environments/` and every link must resolve; every number of two or more digits in it must occur in a file it links to; every `environment-*.json` stored under that directory must be linked from some row. A row without evidence, an invented count and a stored record that the page leaves out each fail, with both sides named.
7. **Failures are listed with what they are.** A failure is reported in the words of the report, with a classification only where the report supports one (a Chromium-only API in the test, a console warning from the three.js baseline); a cause that was not investigated is stated as such. Nothing was changed in the runtime or the compiler to make a browser pass.
8. **What the page may not say.** It makes no statement about an environment it has no record of, says "not covered" for the rest, and marks software-adapter results informational. All local runs came from one machine and one GPU; that is on the page.

## Consequences

- The release notes cite the matrix with its failures: Firefox 155 runs 230 of 251 tests with six failures (one of them a possible runtime difference on a zero-sized canvas, not investigated), the latest `main` run on GitHub Actions is red in `browser-software` with two failures, and no Linux or macOS hardware was available.
- Adding an environment is: run it, store it with `summarize-run.ts`, add its rows; the check names what is missing.
- The Firefox project is a measurement aid, not a promise: it is not run by `npm test`, and Firefox is not listed as supported on this page, only as run, with its failures.

## Verification

`npm run check:release` (`environments/*`); `tools/release-docs/test/units.test.ts` ("supported environments": a row without a stored run, a link that does not resolve, an invented number, an unlisted record, a missing page); the stored runs themselves, listed in [`evidence/M7/environment-matrix.md`](../../evidence/M7/environment-matrix.md).
