# 0026. Types and constant evaluation: details the specification leaves open

- Status: Accepted
- Date: 2026-10-04
- Blueprint origin: §4.1 (numeric semantics), §9.4 (diagnostics); `spec/language.md` §5, §6.2–§6.9, §8.1; `spec/scenes.md` §4.2, §8.3; `spec/compiler-architecture.md` §3, §4.7; decisions 0009, 0024, 0025.

## Context

Task M1-10 implements `crates/mtek-compiler/src/types/`: the type interner, bidirectional checking of the expressions M1 programs use, and constant evaluation (`consteval.rs`), wired into `mtek_compiler::check`. Decision 0025 left the gating of operators, conversions and swizzles to this task. The specification fixes the rules but leaves choices open: which operators M1 implements, how literals meet operators, which folds are errors, the exact operation order of the quaternion functions, what a descriptor literal's type is, and how constants are scheduled. They are fixed here so that they are visible, testable and changeable by a later record.

## Decision

All of the following are **proposals** (design choices), not external constraints.

1. **Operators in M1.** The construct table of decision 0025 gains one row per operator family: unary minus and the arithmetic operators `+ - * /` are implemented in M1 (every row of `spec/language.md` §6.2 for them, including `mat4` and `quat` products, whose operands M1 programs can only form for `quat`); the remainder operator `%`, comparisons, equality and the logical operators `! && ||` are M2. They produce or consume `bool` (used in M1 only as literal field values) or, for `%` on `f32`, need the run-time math library, and they arrive with statements. They are gated by the resolver like every construct (outermost once, `E9010`). **Conversions** `f32(…)`, `i32(…)`, `u32(…)` and **swizzles** are implemented in M1 and have no row (a pass fixture of M1-09 already used `f32(10)`).
2. **Field reads of named objects.** `Cube.position` and `Main.position` are gated by the field's registry `since`, like writing the field. Reading an implemented field has the field's registry type and is never a constant expression; a field the schema does not have is `E5001` (message names the object, a note lists the implemented fields). `E5081` (reading an entity field in an initialiser) stays with the scene checks (M1-11). A bare entity name has the type `entity_ref` (`spec/scenes.md` §8.3: a named entity converts to `entity_ref` where one is expected, its only use as a value). Names of scenes, cameras, functions, structs, materials, prefabs and prelude types, schemas, enums, namespaces and functions are not values (`E3001`).
3. **The checker does not type gated constructs.** It asks the same table and the registry's `since`, gives a gated construct `Ty::Error` without descending and without a diagnostic. A unit test lists every construct the checker skips and asserts it is gated in this build, so a milestone that implements one fails until the checker types it.
4. **Literal expressions.** A literal, or parentheses, unary minus or an arithmetic operator applied only to literal expressions, adopts its type as a whole (`const N: u32 = 16 * 2;` is `u32` arithmetic; `const H: f32 = 1 / 2;` is `0.5`). Next to an operand of known type a literal adopts the scalar type the operator table requires there (`v * 2` with `v: vec3` makes `2` an `f32`; next to an `i32` a float literal is asked to be `i32`, which is `E3041`). The expected type flows into both operands of `+` and `-` and into neither operand of `*` and `/` (they mix types). A conversion requires no particular type of its argument, so a literal argument keeps its default (`f32(10)` converts the `i32` 10; `u32(4294967295)` is `E3041`). A float literal is rounded **once** from its decimal text to binary32; rounding the lexer's `f64` again could differ by one ulp (double rounding). A literal that does not fit `u64` is read from its text.
5. **Non-finite folds are errors.** `spec/language.md` §6.3 makes integer overflow and division by zero during folding `E3040`, matching WGSL const-evaluation. The same holds for an `f32` operation whose folded result is infinite or NaN (WGSL const-evaluation rejects those too, and a folded constant must be emitted as a finite binary32 value): `E3040`. This applies to every fold, wherever the expression appears.
6. **Operation order of the folded quaternion and matrix functions.** Every operation is one binary32 operation, left to right as written:
   - Hamilton product `a * b` of `(x, y, z, w)`: `x = aw*bx + ax*bw + ay*bz - az*by`, `y = aw*by - ax*bz + ay*bw + az*bx`, `z = aw*bz + ax*by - ay*bx + az*bw`, `w = aw*bw - ax*bx - ay*by - az*bz`.
   - `q * v`: `t = 2 * cross(q.xyz, v)`, result `v + q.w * t + cross(q.xyz, t)`.
   - `quat.axis_angle(axis, angle)`: an axis whose components are all zero gives the identity; otherwise the axis is divided by its largest component magnitude (so squaring neither underflows nor overflows), then by the length of the result (`sqrt` of `x*x + y*y + z*z`); with `h = angle * 0.5`, the result is `(n * libm::sinf(h), libm::cosf(h))`. The binary32 `sinf`/`cosf` follow decision 0024 item 6 (`powf` for `color.srgb`).
   - `quat.euler(x, y, z)` is `(axis_angle(+Y, y) * axis_angle(+X, x)) * axis_angle(+Z, z)` (`spec/language.md` §6.7).
   - `mat4 * mat4` and `mat4 * vec4`: each element is `m[0][i]*v[0] + m[1][i]*v[1] + m[2][i]*v[2] + m[3][i]*v[3]`, summed left to right (column-major).
   Run-time evaluation (M2-06) agrees with these within the tolerances of `spec/testing.md` §5; folded constants are emitted, so both domains see the folded bits.
7. **Descriptor literals.** `Box { … }` has the nominal type `Box` (`Ty::Schema`), one type per registry schema, assignable to the registry type of its category: `mesh` for meshes, `material` for materials, the descriptor category (`projection`, `light`, `body`, `collider`) otherwise. Each field value is checked with the field's registry type as expected type (literals adopt it: `segments: 16` is `u32`); whether a value fits its field (`E3102`), unknown, duplicate and missing fields are the schema checks' (M1-11). A folded descriptor is a `ConstValue::Struct` of the fields as written, in source order; defaults are filled in by the schema checks.
8. **Constants.** Every constant is evaluated once, dependencies first: an explicit depth-first search over the uses of constants in initialisers (every name that denotes a constant, also inside gated constructs) gives the order and reports each cycle once (`E2020`, primary span at the first constant of the cycle in source order, one related span per step, the path in the message). No constant evaluation recurses into another constant, so a chain of any length needs a bounded stack. A constant whose value does not have its declared type is `E3001` and has its declared type but no value. A constant whose initialiser is not a constant expression is `E3090` at the first non-constant form (a call of a user function, which is never constant in v0.1 even while functions are gated; a read of `state`, of a parameter or of an entity field; a bare entity name). Other places that demand constant expressions (scene fields, mesh, body and collider descriptors) are the schema checks' (M1-11): `Typeck::non_constant` gives them the reason for each field value.
9. **Codes.** `E3003` is also reported for type arguments on a type that takes none (`vec3<f32, 3>`); unknown type names remain the resolver's `E3003` and are not reported again. `W3050` (a conversion to the type its argument already has) is a compiler warning. Global intrinsics are gated in this build and so is their folding; a unit test fails when one becomes implemented, and another asserts that every const-eligible namespace function the build implements has an evaluator.

## Consequences

- `resolve::Construct` gains `Negation`, `Arithmetic`, `Remainder`, `Comparison`, `Equality` and `Logical`; `gate_*` fixtures cover the gated ones. M2 changes the rows, and the checker then has to type the operators (the unit test of item 3 enforces it).
- M1-11 builds the schema checks on `Typeck` (field value types, folded values, `non_constant`) and owns `E3102`, `E5001`–`E5006` for declarations, `E3090` for fields and `E5081`.
- M1-12 reads folded values from `Typeck::value` and `Typeck::const_info`.
- `spec/compiler-architecture.md` §4.7 points here.
