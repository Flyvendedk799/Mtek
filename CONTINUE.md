## 2. How an area is finished (the method that closed areas 6 and 2)

1. **Contract first.** Before writing code, add a decision record
   `spec/decisions/NNNN-complete-<area>.md` with a numbered acceptance list. Each item
   must be concrete and testable. Reserve the decision numbers of the follow-up work
   and their rows in `spec/decisions/README.md`, and reserve diagnostic codes. Only
   wider physical devices may be deferred, to area 7. Do not relabel hard items as
   "extensions"; area 2 had to undo exactly that.
2. **Check source reach.** In both closed areas the features existed only in host
   TypeScript, and a `.mtek` program could not use them. An area is not done until a
   Mtek program can use it without host code (registry -> type check -> codegen ->
   runtime -> fixtures/goldens -> docs).
3. **Small, reviewable work items.** One decision record per piece, its own branch
   (`task/NNNN-slug`), merged with `--no-ff` into a feature branch
   (`feat/<area>-complete`). Keep evidence apart from code; no commits with thousands
   of files.
4. **Measured claims.** Limits are generated by a script into a spec section between
   markers, with a `--check` mode, and a test asserts them. Examples:
   `ranges:check`, `ccd:check`, `humanoid:check`, `limbs:check`. Never loosen a
   threshold or pick convenient samples. Publish exclusions with their measured
   cause.
5. **A demonstration.** An example written in Mtek, a browser spec on both local
   projects (hardware and software) compared against CPU references, a package
   budget entry and docs.
6. **The full local gate passes**, then mark the area done: the scorecard summary and
   row, the contract's Status line ("met"), and its row in the decisions index. Merge
   into `main` and push only when the owner agrees.

## 3. The local gate (GitHub CI is off on purpose)

CI is disabled for billing reasons and will not be fixed, so the local gate is the
only check. Run it before calling anything done:

```sh
npm run build
npm test                      # check, cargo test, test:unit, coverage, release docs, baseline, test:browser
npm run check:budgets         # package size budgets (budgets/small-games.json); never raise without a reviewed reason
npm run check:prebuilt        # crates/mtek-cli/prebuilt matches the sources (npm run build && npm run prebuilt:write)
npm run ccd:check && npm run ranges:check -w @mtek/physics-rapier
npm run humanoid:check && npm run limbs:check
```

- If memory is tight, run `npm test` in parts, and cargo with `-j 4`.
- After a `cargo clean`, the first build takes about 10–15 minutes.
- A repo test requires `mtek fmt`-canonical example sources. The release-docs test
  compares code blocks quoted in docs against the example sources verbatim.
- New root npm scripts must be listed in `README.md`.
- The cold-start AI context has a 30,000-byte budget and almost no headroom: tighten
  registry doc strings rather than raising it.

## 4. Known state and traps

- **Known failing test (not yet fixed):** `tests/browser/specs/m4/configurator.spec.ts:230`
  ("survives resize") expects 3 live textures and gets 6, on both projects. It fails
  identically on `e31c846a`, before areas 6 and 2, so it is a regression from the
  earlier rendering work.
- **Node 24 is required.** The root `node_modules/@dimforge/rapier3d-compat` is an
  old 0.12; the adapter uses 0.21 from
  `packages/physics-rapier/node_modules`. Read that one's typings.
- **Release games load a split runtime** (decision 0225): `runtime.<h16>.js` (core),
  `physics/<h16>.js` when the program has bodies, and `animation/<h16>.js` when it
  has skins or `clips_from`. The npm entry still exports everything.
- **Git-ignored files.** Example GLB models under `examples/*/models` and
  `examples/*/scene/models` are git-ignored; some are prepared by scripts. A fresh
  clone may need them before coverage or example checks pass.
- **Browser tests and GPUs.** They use the project `hardware` (a real GPU) and
  `software` (SwiftShader). A cloud machine without a GPU only gets meaningful
  `software` runs. Hardware tests report NOT-RUN there unless
  `MTEK_REQUIRE_GPU=1`.
- **Frozen archive.** `benchmarks/results/ai/` is frozen evidence; exclude it from
  searches and never use it as a coding reference (see `AGENTS.md`).
- **Numbering.** The next free decision is **0226**. Recently used diagnostic codes:
  `E5124`, `E7028`, `E8105`, `E8110`–`E8114`, `E9030`. The authoritative list is
  `crates/mtek-compiler/src/diagnostics/codes.rs`.
- **Branch to ask about.** The local branch `codex/improvements-validation` exists
  only on the owner's machine (it is merged into `main`); ask before deleting it.
